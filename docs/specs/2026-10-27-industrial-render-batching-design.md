## 1. 目标

在不改变工业业务接口和标准 Tileset 分发方式的前提下，降低 CPU 提交和 GPU
状态切换成本：

1. 离线将静态、同材质、同绘制语义的网格准备为可连续提交的渲染批次。
2. 运行时优先消费离线批次，不重复执行几何转换。
3. 运行时根据当前可见集合进行轻量批次规划和裁剪。
4. 对确有收益的重组任务使用 Worker，避免阻塞交互主线程。
5. GPU 使用实例化、批量绘制和按顶点语义身份拾取。
6. 不因合批改变设备选择身份、Tileset、LOD 或业务查询结果。
7. 在真实工业资产上把可见 Draw Call 至少降低 50%。

## 2. 当前基线

真实资产预览验证记录了以下基线：

- 6 个初始驻留 Tile 对应约 1,472 次 Draw Call。
- 运动阶段约 1,442 次 Draw Call。
- 停稳阶段曾达到 1,319 次 Draw Call。
- 当前资产包含 1,767 个网格节点和 9,984 个三角形 primitive。
- 共享同一源网格的节点实例数为 0。
- 按材质划分的理论批次约为 3,168 个。

因此：

- 只做几何实例化对当前资产没有收益。
- 静态材质合批是第一优先级。
- 实例化仍需实现，但应服务于后续存在重复设备的资产。
- 只更换图形 API 不能解决连续多个网格提交的结构性问题。

## 3. 核心原则

1. **静态优先**：工业厂房中的设备、建筑和管廊绝大多数在运行期间不改变局部变换。
2. **几何单份**：同一批次的几何只在 CPU 工作区和 GPU 缓冲中存在一份。
3. **生产消费分离**：Worker 准备数据，主线程调度，GPU 执行绘制。
4. **零交互长任务**：相机运动期间不执行大型几何合并或大量 GPU 上传。
5. **原子换批**：新批次完整上传后才替换旧批次，失败时保留旧批次。
6. **身份稳定**：批次内部的顶点或实例保留稳定选择索引，业务身份不随批次变化。
7. **标准分发**：继续使用 OGC 3D Tiles 1.1 Tileset 和标准单 JSON/单 BIN GLB。
8. **默认兼容**：未启用批次信息的既有 Prepared GLB 继续按当前路径加载和绘制。
9. **收益优先**：只有预计收益超过复制、内存和上传成本时才执行运行时重组。
10. **确定性**：相同输入、工具版本和选项产生相同批次边界、顺序和选择映射。

## 4. 分层架构

```text
离线工具链
  网格规范化
    → 世界变换烘焙
    → 按 Tile / 材质 / 绘制模式分组
    → 生成批次缓冲与语义索引
    → Prepared GLB

浏览器运行时
  加载 Prepared GLB
    → 注册离线批次
    → 创建语义节点映射
    → 每帧只裁剪和排序批次
    → GPU 批量绘制 / 实例化 / 语义拾取

可选运行时优化
  相机稳定
    → 估算跨批次重组收益
    → Worker 分片生成候选缓冲
    → 传输 ArrayBuffer
    → 分帧上传 GPU
    → 原子切换新批次世代
```

## 5. 离线静态合批

### 5.1 可合批单元

同一 Tile 中，只有同时满足以下条件的几何可以合批：

- 三角形模式或线模式分别一致。
- 输出材质索引一致。
- 顶点颜色语义一致。
- 边线材质和边线宽度语义一致。
- 几何在运行期间被视为静态。
- 选择身份可以被每顶点或每实例属性表达。

具有不同材质、边线模式或动态变换要求的对象不得合入同一批次。

### 5.2 世界变换

静态批次在工具链中把节点世界变换烘焙到顶点位置。语义节点继续保留原始选择
身份和变换摘要，用于：

- 业务查询。
- 包围盒与投影。
- 选择结果映射。
- 设备定位和标签锚点。

这些语义节点是查询和身份载体，不产生重复绘制。通用 GLB 消费者读取批次 mesh
即可看到完整模型。运行时不得为了合批再次遍历设备层次并重新烘焙顶点。

### 5.3 批次边界

- 不跨 Tile 合批，避免破坏流式加载和卸载边界。
- 不跨材质合批，避免引入新的材质语义。
- 单批次设置三角形和字节上限，避免不可中断的超大上传。
- 批次顺序按材质、绘制模式、选择和稳定哈希排序。
- 相同输入产生稳定批次切分和稳定二进制内容。

### 5.4 语义索引

每个批次提供：

```ts
interface ICERenderBatchSemanticIndex {
  readonly ids: readonly string[];
  readonly nodeIds: readonly string[];
  readonly selectionIds: readonly string[];
}
```

顶点携带稳定的无符号整数语义索引，用于 GPU 拾取。索引只指向当前 Prepared GLB
内的语义表，不记录客户名称、业务文本或运行状态。

选择链路：

```text
GPU picking id
  → semantic index
  → semantic node
  → selectionId
  → 业务信息
```

合批不得改变用户可观察的设备选择结果。

### 5.5 批次报告

工具链报告增加：

- 输入 drawable primitive 数。
- 输出批次和批次片段数。
- 合批前后预计 Draw Call。
- 批次三角形和字节统计。
- 因材质、动态或语义原因未合批的对象数。
- 批次内容摘要。

报告不包含客户名称、源路径、截图或完整语义文本。

## 6. 运行时批次规划

### 6.1 每帧轻量路径

每帧只允许执行以下工作：

- 批次包围盒的视锥和遮挡候选测试。
- 按 GPU 状态、材质和缓冲连续性排序。
- 选择已上传的批次世代。
- 提交批量绘制或实例化绘制。
- 更新只读诊断计数。

该路径不得复制几何，不得创建大数组，不得启动同步 Worker 等待。

### 6.2 实例化

相同几何且有多个节点实例时：

- 顶点和索引只存一份。
- 实例变换进入独立实例属性缓冲。
- 使用一次实例化绘制替代逐节点绘制。
- 每个实例保留语义索引，用于拾取和选择。

当前无共享几何的资产应自动跳过实例化，不产生空批次。

### 6.3 自适应重组

跨批次重组只在相机稳定且进入空闲期后评估。收益估算至少考虑：

```text
estimatedGain =
  estimatedDrawCallsSaved * perDrawSubmissionCost

estimatedCost =
  bytesToCopy / estimatedCopyBandwidth
  + workerPreparationCost
  + estimatedUploadCost
  + retainedMemoryCost
```

只有收益超过成本并达到最小收益阈值时才启动候选任务。

下列任一变化会取消候选任务：

- 相机重新开始运动。
- 可见 Tile 集合发生变化。
- 目标世代被替换。
- 资产被释放。
- 内存或字节预算不足。

### 6.4 世代切换

- 每个批次集合拥有单调递增的 generation。
- 新世代只在全部缓冲上传成功后成为活动世代。
- 切换在同一任务中完成，不出现半新半旧批次。
- 旧世代在切换完成后释放。
- 上传或 Worker 失败时继续使用旧世代，并记录一次去重诊断。

## 7. Worker 设计

### 7.1 任务边界

Worker 可处理：

- 网格合并和索引偏移计算。
- 顶点、索引、颜色和语义属性重排。
- 实例矩阵和选择索引整理。
- 批次包围盒合并。
- 批次收益估算。

Worker 不处理：

- 相机逐帧输入。
- GPU 资源创建。
- 场景节点增删。
- 业务状态和选择 UI。

### 7.2 数据传递

- 输入和输出优先使用 Transferable `ArrayBuffer`，避免主线程再次复制。
- 每个任务明确拥有输入缓冲所有权，转移后调用方不得继续读取。
- `SharedArrayBuffer` 只作为可选的跨源隔离增强，不作为硬依赖。
- Worker 不可用或启动失败时退回离线批次，不影响功能。

### 7.3 Worker 池

- Worker 数默认不超过 `min(4, max(1, hardwareConcurrency - 1))`。
- 任务按可见性和预计收益排序。
- 每类资产同时最多保留一个候选世代。
- 每个任务包含 generation、取消信号和资源预算。
- 过期任务可以被中止，输出必须被丢弃。

### 7.4 主线程预算

- 交互期间运行时重组预算为零。
- 空闲期单次主线程调度和缓冲切换目标低于 4 ms。
- GPU 上传按帧字节预算分片执行。
- 不通过 busy-wait 等待 Worker。

## 8. GPU 设计

### 8.1 WebGL2

- 批次几何和实例矩阵使用静态 GPU 缓冲。
- 每个兼容材质批次以批量绘制或实例化绘制提交。
- 按顶点或实例语义索引渲染拾取附件。
- 拾取结果通过紧凑映射表转换为选择 ID。
- GPU 缓冲按批次世代复用和释放。
- 不为 WebGL2 强行模拟通用 GPU 计算。

### 8.2 后续 WebGPU

WebGPU 后端可在不改变公开场景与业务 API 的前提下增加：

- 计算式视锥和遮挡裁剪。
- GPU 批次压缩。
- 间接绘制。
- 时间戳查询和 GPU 侧性能统计。

WebGPU 迁移不是本阶段前置条件。

## 9. Prepared GLB 契约

合批元数据放在标准 `asset.extras.ice3` 中，保持：

- 单个 JSON chunk。
- 单个 BIN chunk。
- 标准 accessor、bufferView、mesh、node 和 material。
- 不新增私有容器或外部资源。
- Tileset 字段和 `REPLACE` 语义不变。

建议的批次元数据：

```ts
interface ICEPreparedBatchMetadata {
  readonly version: '1.0';
  readonly semanticIds: readonly string[];
  readonly batches: readonly {
    readonly meshIndex: number;
    readonly primitiveIndex: number;
    readonly mode: 4 | 1;
    readonly materialIndex: number;
    readonly triangleCount: number;
    readonly bounds: {
      readonly min: readonly [number, number, number];
      readonly max: readonly [number, number, number];
    };
  }[];
}
```

批次顶点使用保留属性名携带语义索引。未识别该属性的通用消费者仍可读取标准
位置、索引和材质并显示模型。

## 10. 旧资产与 LOD 兼容

- 无批次元数据的资产继续使用现有逐网格路径。
- 合批资产必须产生与未合批资产相同的可见几何、颜色、选择和 LOD 结果。
- Tileset 的粗模、细模、几何误差和渐进覆盖前沿保持不变。
- 批次替换发生在单个 Prepared GLB 内部，不改变 Tile 替换顺序。
- 动态 LOD 切换继续以完整覆盖前沿为单位原子提交。

## 11. 公开 API

业务层继续使用现有场景、选择和查询 API。内部增加：

```ts
type ICERenderBatchingMode = 'asset' | 'adaptive' | 'off';

interface ICERenderBatchingOptions {
  readonly mode: ICERenderBatchingMode;
  readonly maxWorkers?: number;
  readonly idleTaskBudgetMs?: number;
  readonly uploadBytesPerFrame?: number;
  readonly maxExtraGpuBytes?: number;
}
```

- `asset`：只使用离线批次，默认值。
- `adaptive`：允许空闲期 Worker 重组。
- `off`：强制逐网格路径，用于诊断和回归对照。

内部批次对象不暴露 GPU 资源。

## 12. 失败与降级

- 批次元数据无效时拒绝资产。
- 选择索引越界时拒绝资产。
- Worker 失败时保留当前世代。
- GPU 上传失败时释放候选资源并保留旧世代。
- 超过额外内存预算时不启动自适应重组。
- 实例化扩展不可用时回退到普通批量绘制。
- 任一降级必须产生稳定诊断码，并保证画面身份和选择可用。

## 13. 测试策略

### 13.1 工具链

- 同材质三角形稳定合批。
- 不同材质、模式、颜色语义不混合。
- 合批输出确定性字节一致。
- 语义索引和设备选择映射完整。
- 世界变换烘焙与未合批运行时世界坐标一致。
- 超大批次按稳定上限切分。
- 批次报告统计准确且不泄露客户内容。

### 13.2 运行时

- 合批与逐网格路径产生相同可见表面。
- GPU 拾取逐个设备返回相同 `selectionId`。
- 多节点共享几何时只上传一份几何。
- 批次裁剪结果与逐网格裁剪一致。
- 切换 LOD 时批次和语义映射同步替换。
- 取消、失败、上下文恢复和释放不泄漏 GPU 资源。

### 13.3 Worker

- 任务使用 Transferable 缓冲，不发生隐式复制。
- 相机变化后过期任务结果被丢弃。
- Worker 不可用时可回退。
- Worker 池遵守并发上限。
- 释放资产时所有任务和缓冲被取消。

### 13.4 性能

- 真实工业资产可见 Draw Call 至少降低 50%。
- 运动期间不得出现超过一帧预算的主线程长任务。
- 空闲重组期间输入响应保持可用。
- 批次世代切换不产生空帧或父子重叠。
- 初始加载内存增加不超过配置上限。

## 14. 非目标

本阶段不包含：

- 动态物体逐帧重新合批。
- 动画、蒙皮或骨骼批次。
- 纹理图集或复杂 PBR 合批。
- 运行时网格简化。
- 体素化、HLOD 合并或设备簇代理。
- 改变设备选择身份或业务查询模型。
- 以 WebGPU 替换现有 WebGL2 最低运行要求。

## 15. 实施阶段

1. **离线批次与契约**
   - 定义批次元数据和语义索引。
   - 工具链生成确定性静态批次。
   - 未启用批次时保持字节兼容。

2. **运行时 WebGL2 消费**
   - 加载批次元数据。
   - 按批次绘制和拾取。
   - 保留逐网格降级路径。

3. **批次规划与实例化**
   - 批次级裁剪和稳定排序。
   - 共享几何实例化。
   - 输出前后 Draw Call 和 GPU 字节指标。

4. **Worker 自适应重组**
   - Worker 池、Transferable 数据流和取消机制。
   - 空闲收益评估。
   - 分帧上传和世代原子切换。

5. **现代后端扩展**
   - 在 WebGPU 后端实现计算式剔除和间接绘制。

## 16. 验收标准

本规格完成时：

1. 现有未合批资产和公开 API 保持兼容。
2. 真实资产使用离线批次后可见 Draw Call 下降至少 50%。
3. 合批前后设备选择、业务身份、LOD 和画面结构一致。
4. 大型运行时重组不进入交互帧，并可被取消。
5. Worker、GPU 上传或批次切换失败都能安全回退。
6. 浏览器矩阵覆盖 Chromium 和 WebKit。
7. 客户资产及其派生内容不进入仓库、日志、截图或发布包。

## 17. 实现与验收结果

离线静态合批、Prepared GLB 批次契约、WebGL2 批次提交、按顶点语义拾取、
选择高亮和共享几何实例化均已实现。没有批次元数据的既有资产继续使用普通
网格路径；工具链默认值保持 `--render-batch off`，需要在准备阶段显式开启
`static`，以保证既有输出字节和发布流程不变。

在边缘线关闭、分区与 LOD 参数一致的受控工业资产上，普通路径和静态批次
路径的浏览器可见结果如下：

| 指标 | 普通网格 | 静态批次 |
| --- | ---: | ---: |
| 源三角形 | 16,939,337 | 16,939,337 |
| 输入可绘制 primitive | 1,472 | 1,472 |
| 可见 Draw Call | 1,472 | 662 |
| Draw Call 降幅 | 0% | 55.03% |
| 输出字节 | 406,072,056 | 476,678,116 |
| 构建墙钟时间 | 22.68 s | 40.77 s |
| 峰值常驻内存 | 4.64 GiB | 3.42 GiB |
| 稳定选择身份 | 261 | 261 |
| 页面错误 / 失败请求 | 0 / 0 | 0 / 0 |

开启同参数比例 LOD 后，完整输出为 108 个 GLB、107 个 Tile。批次报告覆盖
细模和粗模共 9,984 个输入 primitive，生成 2,079 个批次，报告降幅为
79.18%。全部 GLB 通过结构校验，261 个语义选择身份与未合批输出一致，粗模
覆盖和渐进替换保持正常。在相同相机和 45 秒观测窗口内，Chromium 的活跃
LOD 工作集从 1,472 次普通 Draw Call 降至 114 次批次 Draw Call。

批次方案以更高的预处理字节数和更长的离线构建时间换取运行时 CPU 提交量
下降。当前资产没有共享源网格，因此静态材质合批承担主要收益；实例化路径
通过独立共享几何样例验证，4 个实例合并为 1 次绘制。真实资产在 Chromium
与 WebKit 中均无页面错误或失败请求。

运行时批次和实例化消费预处理结果，不在浏览器执行几何格式转换或简化。
可选的 `adaptive` 模式在相机和可见集稳定后评估跨批次重组，使用有界 Worker
池生成可转移缓冲，并按帧上传候选世代。相机重新运动、可见集变化或资产释放
会取消候选并恢复当前活动世代；Worker 或上传失败不会替换活动批次。

自适应模式默认关闭，Tileset 默认继续使用 `asset` 离线批次。自动化覆盖相机
移动期间不启动候选、Worker 池并发上限、Transferable 所有权、候选失败回滚、
帧字节预算、完成前不激活、过期世代丢弃、原子切换、选择身份保持，以及
Chromium/WebKit 的完整交互路径。

### 17.1 GPU 驻留稳定性

CPU 驻留、视锥可见性和 GPU 驻留是独立状态。Tile 一旦成功驻留，其 GPU 几何
保留到 Tile 真正卸载，不因暂时离开视野或 LOD 覆盖切换而释放。新 Tile 在
隐藏状态下完成几何上传后才允许显示；相机运动期间继续显示当前完整覆盖，
直到下一份完整覆盖已经 GPU Ready 后原子替换。

未归 Tile 所有的几何至少在连续 60 个未使用帧内可复用；默认 768 MiB 几何
预算按最近最少使用顺序淘汰非固定资源。默认驻留上限调整为 64 个 Tile 和
768 MiB，使受控资产的 54 个 Tile、约 469 MB GPU 工作集保持稳定。
默认保留光晕覆盖完整资产半径，因此相机自身运动不会触发 Tile 卸载；只有
驻留数量或字节预算超限时才淘汰离屏内容。
相机运动时，空间上互不替代且已经 GPU Ready 的 Tile 会立即进入可见覆盖；
只有同一空间区域内的粗细层级替换继续等待相机稳定和完整覆盖就绪，避免粗模
与细模重叠或缺帧。

渲染诊断增加累计 `gpuUploads` 与 `gpuEvictions`。稳定旋转测试要求已驻留
内容重新进入视野时不增加上传或淘汰计数，并保持完整可见覆盖。
