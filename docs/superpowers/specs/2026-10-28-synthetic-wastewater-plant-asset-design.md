# 虚构污水处理厂三维资产设计规格

| 项目 | 内容 |
| --- | --- |
| 状态 | 已实施，持续增强 |
| 版本 | 1.1 |
| 日期 | 2026-10-28 |
| 适用范围 | 虚拟污水厂生成器、GLB 源资产、预处理、空间拆分、LOD 粗模和示例集成 |
| 前置条件 | 现有 GLB 预处理、空间拆分、LOD 粗模、语义选择与 Tileset 运行时已合入 `main` |

## 1. 目标

生成一个完全虚构、可以公开分发和提交的市政污水处理厂三维资产，替代当前示例中的简化占位资产，作为工业场景、设备选择、空间分区、LOD 和后续工业语义层的正式演示数据。

该资产必须满足：

- 不读取、不复制、不派生任何真实客户模型或其属性。
- 使用自行生成的几何、材质、节点层级、设备编号和文本信息。
- 呈现完整且可信的市政污水处理主流程，而不是抽象方盒。
- 总览时依靠池型、设备剪影和分区识别完整工艺，近景时提供可辨认的机械与检修细节。
- 每个主要工艺设备具有稳定、唯一、可选择的空间身份。
- 输出标准 GLB，并走完 prepared GLB、空间拆分、LOD 粗模和粗模分块流程。
- 浏览器运行时只加载预处理结果，不执行模型生成或格式转换。
- 资产可由仓库内的生成器确定性重建。

## 2. 调研输入与边界

现有二维智慧水务示例提供业务流程参考，使用的主流程为：

```text
厂外进水
  → 粗格栅
  → 进水泵
  → 细格栅
  → 曝气沉砂池
  → 初沉池
  → 配水井
  → 厌氧池
  → 缺氧池
  → 好氧池
  → 二沉池
  → 中间提升泵
  → 混凝沉淀池
  → 滤布滤池
  → 深度处理
  → 消毒接触池
  → 在线监测与计量
  → 排放口
```

配套工艺包括：

- 污泥回流和剩余污泥。
- 污泥浓缩、厌氧消化、沼气处理和脱水暂存。
- 鼓风曝气。
- 化学加药。
- 事故水收集和回流。
- 滤池反冲洗回流。
- 出水在线水质仪表。

本项目只参考上述业务语义，不复制二维图元、布局坐标、脚本、Agent 事件或交互数据，也不实现任何 Agent 接入。

## 3. 工具选型

采用 `@gltf-transform/core` 作为构建期 GLB 生成 SDK，并在 TypeScript 中实现确定性的几何与场景组装。

选择理由：

- 原生支持 glTF 2.0 场景、节点、网格、图元、材质、访问器和二进制 GLB。
- 可直接写入节点名称、矩阵和扩展元数据。
- 与现有 Node.js、TypeScript 和预处理工具链一致。
- 可在测试中验证资产结构和导出确定性。
- 只作为离线开发依赖，不进入浏览器运行时。

不采用外部可视化建模软件作为必需构建步骤，因为它会增加工具安装、版本漂移和不可自动复现的问题。

不手工拼接 GLB 二进制，因为层级、访问器、对齐和材质关系容易产生难诊断错误。

## 4. 虚拟厂区设计

### 4.1 总体布局

厂区采用紧凑矩形布局，主轴从西向东：

- 西侧：进水、粗格栅、进水泵房和细格栅。
- 中西段：沉砂、初沉、配水和两组并联生化线。
- 中段：两组二沉池及中间提升。
- 东侧：混凝、过滤、深度处理和消毒。
- 南侧：污泥处理、鼓风机房、加药间和事故池。
- 北侧：巡检通道、控制建筑和出水监测。

两组生化线保持视觉对称但设备 ID 独立。主要池体之间使用高架管线、地埋管线示意和巡检平台连接。

### 4.2 设备清单

第一版至少包含以下可选择设备组：

| 工艺区域 | 设备 |
| --- | --- |
| 进水区 | 进水口、粗格栅、进水泵 A/B、出水止回阀、细格栅 |
| 预处理区 | 曝气沉砂池、砂水分离器、初沉池及刮泥机构 |
| 配水区 | 配水井、事故池、事故水回流泵 |
| 生化区 | 厌氧池 A/B、缺氧池 A/B、好氧池 A/B、鼓风机 A/B、回流污泥泵、剩余污泥泵 |
| 二沉区 | 二沉池 A/B、中心传动刮泥机、中间提升泵 A/B |
| 深度处理区 | 混凝沉淀池、加药装置、滤布滤池、反冲洗泵 |
| 消毒与排放区 | 消毒接触池、紫外消毒渠道、出水阀、在线监测仪、流量计和排放口 |
| 污泥区 | 污泥浓缩池、厌氧消化池、沼气火炬、脱水机、干化机、污泥料仓和输送机构 |

具体节点数量可根据视觉密度调整，但每个主流程设备必须独立存在，不能被合批后丢失选择身份。

### 4.3 几何表现

使用程序化基础几何组合表达工业构筑物：

- 矩形池体：底板、池壁、水面、走道和栏杆。
- 圆形池体：环形池壁、中心机构、跨桥和栏杆。
- 圆形池体增加中心进水井、旋转半桥、中心驱动、刮泥臂、出水槽、浮渣挡板和污泥斗。
- 生化池增加分格导流墙、池顶巡检平台、搅拌器、曝气器阵列、空气总管和支管。
- 泵组：底座、泵体、电机、联轴器和接管。
- 风机和脱水设备：撬装底座、消声罩、检修面板、进风过滤、出风汇管、絮凝槽和泥饼输出。
- 阀门和仪表：阀体、手轮或执行器、立杆、箱体和显示面板。
- 管线：直管、弯头和法兰环，按水体、污泥、空气和药液分色。
- 建筑：控制室、加药间和设备房，包含门、窗、雨棚、屋顶设备与差异化体量。
- 厂区：覆盖完整设备范围的硬化地坪、道路、路缘、围墙、管廊、支墩、楼梯和检修平台。

### 4.4 细节与性能预算

- 同一设备内按材质合并图元，避免机械细节不受控地增加 draw call。
- source 目标范围为 4 万至 10 万三角形，当前基线约为 7.9 万三角形。
- 细模以 6000 三角形为单块上限，粗模总预算为 2.4 万三角形，并按 512 KiB 上限分块。
- 围墙等跨厂区的细长结构按方向拆分，避免粗模包围体覆盖整片厂区并遮挡设备选择。
- 同一厂区内的设备包围体不得发生实质空间交叠。

### 4.5 视觉参考边界

公开实景照片、工艺剖面、设备安装图和 3D 效果仅用于提炼结构关系与视觉层级。
不下载、不复用或改编第三方模型、贴图、动画和具体企业设计资料。

不依赖贴图，使用基础颜色和顶点色表达材质。主体采用中性混凝土灰、设备蓝绿、管道分区色、水面深蓝和高亮黄色选择反馈。

## 5. 场景与语义结构

### 5.1 层级

```text
SyntheticWastewaterPlant
  ├─ WaterTreatmentArea
  │   ├─ IntakeArea
  │   ├─ PrimaryTreatmentArea
  │   ├─ BiologicalTrainA
  │   ├─ BiologicalTrainB
  │   ├─ SecondaryTreatmentArea
  │   ├─ AdvancedTreatmentArea
  │   └─ DischargeArea
  ├─ SludgeTreatmentArea
  ├─ ChemicalDosingArea
  ├─ UtilitiesArea
  └─ SiteInfrastructure
```

非设备节点用于组织区域和附属几何，不进入设备选择结果。

### 5.2 稳定身份

每个设备节点必须具有：

```ts
interface ICEWastewaterEquipmentIdentity {
  readonly selectionId: string;
  readonly equipmentTag: string;
  readonly processStage: string;
  readonly displayName: string;
}
```

身份采用虚构、稳定的前缀，例如：

```text
ice3-virtual-wwtp/equipment/IN-101
ice3-virtual-wwtp/equipment/BLWR-101
ice3-virtual-wwtp/equipment/SC-201
```

节点名称、选择身份和设备编号在重复生成时必须一致，不依赖数组遍历顺序。

### 5.3 材质

第一版材质集合固定为：

- 混凝土。
- 设备金属。
- 水体。
- 空气管。
- 污水管。
- 污泥管。
- 药液管。
- 安全黄。
- 监测与控制设备。

材质通过名称和基础颜色区分，不引入纹理、法线贴图或复杂物理材质。

## 6. 生成器结构

在预处理工具工程中新增独立生成器：

```text
ice3-toolchain/
  tools/
    wastewater-plant/
      generate.ts
      layout.ts
      primitives.ts
      equipment.ts
      palette.ts
```

职责：

- `layout.ts`：区域、管线、道路、平台和整体坐标。
- `primitives.ts`：箱体、圆柱、环形池、管线、栏杆、设备组合等几何。
- `equipment.ts`：设备清单、稳定身份和工艺归属。
- `palette.ts`：固定材质和颜色。
- `generate.ts`：组装 glTF 场景、写入元数据并导出 source GLB。

生成器必须接受固定输出路径和资产 ID，不读取环境中的客户资产路径。

## 7. 资产产物

生成后的资产位于引擎示例资产目录：

```text
examples/m1/assets/wastewater-plant/
  source/
    wastewater-plant.glb
  prepared/
    wastewater-plant.glb
  tiled/
    tileset.json
    parts/
      part-000.glb
      ...
    coarse/
      coarse-000.glb
      ...
```

规则：

- `source` 是生成器直接输出的标准 GLB。
- `prepared` 是经过现有预处理工具生成的运行时资产。
- `tiled` 是 source 资产的原始几何经过空间拆分和 LOD 生成后的 Tileset。
- 空间拆分直接消费 source，避免把 prepared 中生成的边线图元当作模型三角形再次拆分；切出的每个运行时片段仍由现有流程输出 prepared profile。
- 粗模必须实际生成并按照 `coarse-chunk-max-bytes` 分块。
- 所有产物均为虚构数据，可以进入版本库。
- 生成报告不写入客户路径或本机临时目录。

## 8. 预处理流水线

完整流水线固定为：

1. 执行生成器，输出 source GLB。
2. 使用预处理工具验证 source。
3. 生成单文件 prepared GLB。
4. 以 source 的原始几何执行空间拆分。
5. 同时生成 LOD 粗模。
6. 对粗模应用明确的分块字节上限。
7. 根据资产预算选择静态离屏合批。
8. 验证 Tileset、分区 GLB、粗模 GLB、身份和统计数据。

具体阈值由实施计划根据实际几何预算确定，但必须确保：

- fine partition 数量大于一。
- coarse content 数量大于一。
- 至少触发一次粗模分块。
- 每个设备选择身份在可见语义节点中出现。

## 9. 示例集成

无本地客户模型时，根路径默认加载虚拟污水厂 tiled 资产。

本地客户预览仍保持最高优先级，并继续通过忽略的本地引用访问。页面不得在诊断、DOM、日志或网络请求中暴露客户文件名。

示例保留现有能力：

- 大平光渲染和清晰边线。
- 鼠标旋转、滚轮缩放、键盘平移。
- 加载状态。
- 设备点击选择与右上角属性浮层。
- Tileset 进度、LOD 状态和资产释放。

如果当前相机处于总览距离，应显示可辨识的完整厂区粗模，而不是空场景或少量占位方盒。

## 10. 错误处理

生成器使用稳定错误码：

```text
ICE3_WWTP_LAYOUT_INVALID
ICE3_WWTP_EQUIPMENT_DUPLICATE
ICE3_WWTP_GEOMETRY_INVALID
ICE3_WWTP_EXPORT_FAILED
ICE3_WWTP_ARTIFACT_INVALID
```

任一步失败时：

- 不发布不完整 GLB。
- 不覆盖现有有效资产。
- 不留下部分 Tileset。
- 诊断不包含客户路径或客户文件名。

## 11. 测试策略

### 11.1 生成器

- 相同输入生成字节一致的 source GLB。
- 构图包含完整主流程和所有设备区域。
- 设备 ID、设备编号和选择身份唯一。
- 所有设备矩阵和顶点数值有限。
- 不存在纹理、动画、外部资源和客户身份。

### 11.2 预处理与拆分

- source 和 prepared GLB 通过现有验证器。
- Tileset、所有 fine partition 和所有 coarse chunk 可加载。
- 粗模包含完整厂区覆盖。
- 拆分阈值实际产生多个 fine 和 coarse 文件。
- prepared 与 tiled 资产的选择身份一致。

### 11.3 浏览器

- 无客户本地预览时，根路径加载虚拟污水厂。
- 有本地预览时，本地模型仍优先。
- 页面无脚本错误和失败请求。
- 完整厂区在初始视角可见。
- 主要设备可点击，黄色高亮明显，属性浮层内容正确。
- LOD 切换、相机移动、选择和释放流程稳定。

## 12. 验收标准

1. 生成器可通过一条命令重建整个虚拟污水厂。
2. 生成资产不包含任何客户数据或外部派生内容。
3. 厂区包含完整主流程、污泥、加药、鼓风和监测系统。
4. 主要设备具有稳定、唯一、可选择身份。
5. source、prepared、fine partition 和 coarse chunk 全部通过验证。
6. 拆分、粗模生成和粗模分块均实际发生。
7. 示例根路径默认展示虚拟污水厂，且视觉可辨识。
8. 本地客户预览覆盖机制继续工作。
9. 完整单元、集成和浏览器验证通过。
10. 代码、文档、提交信息和包产物不含客户资产或禁止名称。

## 13. 非目标

- 真实工程级水力计算和构筑物尺寸校核。
- 施工图、工程量清单或设备选型。
- 高精度建筑信息模型。
- 纹理、物理材质、动画和粒子水体。
- 实时工艺仿真、控制逻辑或告警规则。
- Agent、Prompt、模型调度或 AI 专用接口。
- 读取或转换客户模型。
- 浏览器内实时建模或格式转换。
