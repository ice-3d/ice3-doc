# 高可信度污水处理厂三维资产生成规格

| 项目 | 内容 |
| --- | --- |
| 状态 | 已评审 |
| 版本 | 1.1 |
| 日期 | 2026-10-28 |
| 适用范围 | 虚构污水厂构建期资产生成、GLB 导出和现有预处理流水线接入 |

## 1. 目标

把当前基于基础三角面拼接的虚构污水厂替换为结构更完整、近景更可信的资产，同时保留现有引擎运行架构。

验收不是追求照片级渲染，也不是制作施工级 CAD 模型，而是达到可以直接用于客户演示的工业场景质量：

- 总览距离能辨认完整厂区和主要工艺组团。
- 设备名称、外形和空间关系符合常见市政污水厂。
- 近景能看到栏杆、楼梯、平台、桥架、管道、阀门和驱动机构等工业细节。
- 主要设备端口、工艺管线、回流支路和公用工程管线形成可验证的拓扑关系，而不是装饰性管线。
- 不依赖写实贴图、复杂灯光或阴影来掩盖几何问题。
- 65 个已有设备身份和后续新增设备身份保持稳定。

## 2. 当前问题

现有工具链通过项目内几何函数直接生成三角面。它适合验证格式和运行时，但缺少成熟建模能力：

- 方盒和圆柱只能表达基础体量，倒角、过渡、壁厚和局部切除能力有限。
- 管道连接、桁架、楼梯、格栅和检修设施的代码复杂且重复。
- 大量细节依靠手工堆叠基础几何，视觉上容易形成“积木感”。
- 提高面数不能自动改善识别度，设备仍缺少真实结构的连接关系。

## 3. 工具决策

采用 Blender 5.2.3 的 Python API 和无界面模式，作为唯一的虚构污水厂模型生产工具。

原因：

- 支持通过 Python 创建完整场景并批量导出 GLB。
- 支持倒角、布尔、阵列、曲线管道和几何节点等成熟建模能力。
- 支持在对象自定义属性中保存数据，并在 glTF 导出时写入 `extras`。
- 能在无图形界面环境中运行，适合本地脚本和持续集成。
- 版本稳定、社区成熟，不需要把编辑器交付给最终用户。

Blender 只作为构建期工具。浏览器运行时、预处理、空间拆分、LOD、静态合批和交互选择不依赖 Blender。

不采用在线生成式三维服务，因为结果不可稳定复现，设备结构不可精确约束，授权与商业使用边界也不适合作为基础资产链路。

## 4. 总体架构

```text
TypeScript 场景规格
  → 规范化构建 JSON
  → Blender 无界面 Python 生成器
  → 高精度 source GLB
  → 现有 prepared、拆分、LOD 和静态合批流水线
  → Tileset
  → ICE3 浏览器运行时
```

职责边界：

- TypeScript 继续维护设备编号、名称、工艺阶段、类型、位置和区域。
- 构建 JSON 是工具间稳定接口，只包含生成模型所需的数据。
- Blender Python 负责几何、层级、材质、构件细节和 GLB 导出。
- 现有校验和运行时资产格式保持不变。
- 浏览器运行时不得出现 Blender、Python 或运行时格式转换依赖。

## 5. 场景规格

### 5.1 厂区结构

- 厂区应包含完整地坪、道路、路缘、围墙、出入口、管廊和主要检修通道。
- 西侧布置进水、格栅、提升泵房、沉砂和初沉区。
- 中部布置两组并联厌氧、缺氧和好氧生物处理线。
- 生物处理线后接圆形二沉池、回流污泥和剩余污泥泵站。
- 东侧布置混凝、沉淀、过滤、深度处理和消毒设施。
- 南侧布置污泥浓缩、厌氧消化、沼气处理、脱水和储运设施。
- 北侧布置控制、检修和辅助建筑。
- 建筑之间应有明确的道路开口、门、窗、雨棚、通风和屋顶设备。

### 5.2 设备细节

设备生成应使用独立原型，而不是共享通用方盒：

- 机械格栅：进水渠道、倾斜栅条、耙齿、链条或液压机构、顶部电机、栅渣槽和收集容器。
- 泵组：混凝土基础、钢制底座、泵体、电机、联轴器防护、进出水管道、阀门和仪表。
- 沉砂池：矩形池体、曝气支管、沉砂桥、刮板、砂水分离器和排砂管。
- 矩形初沉池：链板或跨桥刮泥机构、出水堰、排泥斗和检修平台。
- 圆形沉淀池：中心进水井、旋转半桥、中心驱动、刮泥臂、出水堰槽、浮渣挡板和污泥斗。
- 生化池：分格池体、导流墙、中央巡检平台、双层栏杆、搅拌器、曝气盘、空气总管和支管。
- 鼓风机：撬装底座、消声罩、进风过滤、叶轮或罗茨机壳、电机、软接头、止回阀和出风汇管。
- 污泥脱水：污泥储罐、混合絮凝槽、加药装置、螺旋挤压机、冲洗水、滤液回流和泥饼输送链。
- 消化池：圆柱池体、锥形或拱形顶、检修环道、气体管、阀门和沼气火炬。
- UV 消毒：开放式渠道、不锈钢灯架、灯管模块、石英套管、擦洗机构和控制柜。

### 5.3 建模方式

- 主体尺寸由明确的工艺规格驱动，不随机布置。
- 使用倒角、实体壁厚和连接构造减少方盒感。
- 管道使用曲线或扫掠体，弯头、法兰、支架和阀门应有明确连接逻辑。
- 楼梯、栏杆、格栅步道和支墩通过可复用组件或几何节点生成。
- 保留建筑和设备的独立对象层级，以便写入语义身份和后续 LOD 处理。
- 仅在导出时应用建模修改器，GLB 不依赖 Blender 专有修改器。
- 设备必须声明稳定端口，端口包含介质、公称直径、方向和空间位置；工艺连接只能引用这些端口。
- 管线从上游端口连续生成到下游端口，并在需要跨越道路或设备时经过管架、支吊架和可识别的弯头。
- 主工艺、两条生物处理线、回流污泥、剩余污泥、曝气、药剂、反冲洗、滤液、沼气和在线仪表取样应形成独立管线网络。

## 6. 视觉约束

- 不依赖纹理贴图、法线贴图或复杂物理材质。
- 默认展示保持黑背景和大平光。
- 使用受控的混凝土、钢构、设备、水体、污泥、空气管、水管、药液管、警戒色和玻璃灰阶。
- 几何轮廓、连接关系和遮挡层次承担主要真实感。
- 不对全部网格生成统一白色描边；结构辨识依赖真实几何、面朝向、材质分区和受控明暗关系。选中设备保留高对比黄色高亮。
- 总览视角优先展示完整厂区轮廓和工艺流程组团。
- 近景视角优先展示设备结构、平台、管道和检修关系。

## 7. 语义身份

每个可选设备导出一个稳定的顶层对象，并写入 glTF `extras`：

```json
{
  "ice3": {
    "selectionId": "ice3-virtual-wwtp/equipment/P-101",
    "equipmentTag": "P-101",
    "processStage": "intake",
    "displayName": "进水泵 A",
    "area": "IntakeArea",
    "ports": ["suction", "discharge"],
    "connections": ["main-03-P-101-CV-101"]
  }
}
```

规则：

- 设备子构件可以独立存在，但不得生成冲突的选择身份。
- 区域、道路、建筑外壳、管廊和围栏不得冒充设备身份。
- 管线节点记录连接编号、上下游端口、介质和公称直径，使业务层无需解析几何即可理解流向。
- 所有连接端点必须指向存在的设备端口，所有设备至少参与一个连接。
- 导出后由现有校验器分别核对 source、prepared、fine 和 coarse 的设备身份。

## 8. 构建与错误处理

- Blender 版本固定为 5.2.3；检测到其他版本时明确失败。
- 构建命令通过 `BLENDER_BIN` 覆盖可执行文件路径，默认使用标准安装位置。
- 生成器只读取仓库内的场景规格和模板，不读取客户目录、环境中的模型路径或网络资源。
- 所有中间文件写入临时 staging 目录。
- 导出后先验证 GLB 结构、网格数量、设备身份、边界和禁止内容，再替换现有 source 资产。
- 任一步失败时旧资产保持不变，并清理 staging 目录。
- 不允许在 Blender 不可用时静默回退到旧生成器。

## 9. 性能预算

- source 目标范围为 60 万至 200 万三角形，优先增加可识别结构与连接细节，不为凑数做无意义细分。
- 源 GLB 和派生资产不以“越小越好”为目标；允许使用更大的预处理资产换取近景几何质量，运行时继续依靠分区和 LOD 控制负载。
- 单个主体设备可根据真实结构复杂度超过 1 万三角形，但不得依靠表面细分替代设备构造。
- 细模单块上限暂定 60000 三角形，按运行时网络和性能实测调整。
- 粗模总预算继续按设备保真和总览清晰度独立校准。
- prepared、Tileset 和静态合批后必须保持浏览器可交互帧率。
- 细节增长不得导致 65 个设备身份丢失或粗模遮挡选择。

## 10. 测试与验收

### 10.1 自动验证

- TypeScript 场景规格完整性、唯一设备和区域归属。
- Blender 生成器在固定版本下成功导出 GLB。
- 两次生成产生相同 GLB 哈希。
- source 与现有 prepared 校验器兼容。
- source、prepared、fine 和 coarse 均包含完整设备身份集合。
- 设备端口、管线端点和业务连接全部可解析，所有设备至少参与一个有效连接。
- 该示例资产不生成统一描边几何，选中高亮仍由运行时完成。
- 资产不包含纹理、客户路径、外部资源或禁止名称。
- 现有工具链和引擎全量单元、集成及浏览器测试通过。

### 10.2 视觉验收

- 生成总览、工艺区和设备近景三个固定机位截图。
- 总览中可以辨认进水区、两条生化线、二沉池、深度处理区和污泥区。
- 近景中可以辨认格栅、泵组、沉淀池驱动机构、曝气池平台和鼓风机组。
- 连续缩放、旋转和 LOD 切换时，设备不得退化为无法识别的简单方盒。
- 直线重复、构件穿模、悬空管道和非法空间交叠不得出现。

## 11. 非目标

- 不构建通用 CAD 编辑器。
- 不把 Blender 或任何建模工具嵌入浏览器。
- 不追求施工级尺寸、工程量或水力计算。
- 不引入真实工程模型、厂商受保护图纸或第三方模型资产。
- 不实现 Agent、Prompt 或 AI 专用接口。
